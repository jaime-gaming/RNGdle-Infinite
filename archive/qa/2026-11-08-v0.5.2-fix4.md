# v0.5.2 fix4 — compressed saves, 10,000-entry history and the blank loader — 2026-11-08

## Requested changes

- Internal label is `RNGdle-Infinitev0.5.2fix4` in `src/app-update.js`,
  `vite.config.js`, the version test, AGENTS.md and the generated `docs/`
  metadata. Public release notes in `src/changelog.js` were left byte-for-byte
  unchanged; the historical “6,000 rolls / warns at 4,500” entry stays verbatim.
- Primary saves are **always** the `rngvault1:` gzip/base64 envelope. This
  reverses the old “JSON normally, compress only after a quota error” contract.
  `writeDeviceSave` decodes the incoming save, re-packs it, verifies the exact
  round trip and writes only the packed form; a failed write leaves the previous
  save untouched. Plain-JSON saves from older builds remain readable, with no
  migration. History, recovery copies and owner markers are never deleted.
- `HISTORY_LIMIT` is 10,000. `HISTORY_WARNING` is 7,500 — the same 75% ratio
  the old 4,500/6,000 pair used, kept as a provisional value because the request
  specified only the cap. Comments, UI copy and pinned tests read the constants
  instead of hardcoded numbers.
- AGENTS.md gained the “Compressed primary saves” contract and the blank
  loading-screen rule; README and About now describe always-compressed local
  saves. Tests that read raw primary JSON were moved to the shared
  `tests/helpers/save.js` decoder (`unpackVaultSave`), and the Worker smoke tool
  decodes the same way. Saves that a test patches are written back as plain JSON;
  the app immediately re-packs them on its next write.
- `src/components/LoadingScreen.jsx` renders one 44px circle on an otherwise
  empty themed page: no visible text, logo, artwork or extra graphics. It has
  `role="status"` and a screen-reader-only `aria-label="Loading"`; the label is
  an attribute, not page content, and the DOM text of the screen is empty. The
  circle is a single CSS border spinner with a reduced-motion breathe variant.
- `shouldShowLoadingScreen` in `src/loading-gate.js` owns the decision: data not
  ready, auth resolving, or an authenticated profile not yet synced. Conflict,
  load error, offline and maintenance states keep the normal interface so the
  player can choose or retry. `src/main.jsx` returns the loader before rendering
  the header, footer, banners, `InstallApp`, `MobileTabBar`, modals or toasts, so
  nothing else is on the page. Partial loaders were superseded: the roll button's
  “LOADING ROLL DATA…” copy and its screen-reader status are gone, the Cloud
  Account status spinner is gone, and the Cloud Profile card wait uses the same
  blank screen. `OfflineRewards.jsx` had no loader to remove.
- Local progress is persisted before any cloud request and again (with a dirty
  marker) when a cloud load fails, so waiting for sync cannot cost local
  progress. The cloud gate, ownership checks, durable-progress comparison,
  conflict recovery and `cloud.ready` gating are unchanged: local data is the
  starting point, and an authoritative cloud document still wins through the
  existing reconciliation. No security or merge contract was weakened.
- AI audit only, as requested: no AI/IA text, model names, generated-art claims
  or AI references in source, tests, README, legal pages, changelog, public
  assets or the regenerated `docs/` bundles. Generated scoring tables, Firebase
  `AIza…` public keys, integrity hashes and the 🤖 “Binary Soul” badge are
  unrelated; the hand-drawn icon geometry and its “original” notes were kept.
