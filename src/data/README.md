# Full-range scoring data and reference fixtures

Retrieved on 2026-09-14 from [RNGdle Tools](https://rng.cubityfir.st/), pinned to commit [`8190166af9f259a9d3a0a941b2c9902bfbbe713f`](https://github.com/CubityFirst/rngdle-ep-calculator/tree/8190166af9f259a9d3a0a941b2c9902bfbbe713f).

## Files and provenance

- `public/data/ep-table.bin.gz`: factual total EP for each integer **0 through 1,000,000 inclusive**. Upstream path: `site/ep-table.bin.gz`. 2,099,404 compressed bytes; 4,000,004 inflated bytes. Little-endian unsigned 32-bit EP at offset `4 × number`.
- `public/data/badge-table.bin.gz`: factual earned-badge membership. Upstream path: `site/badge-table.bin.gz`. 395,276 compressed bytes; 29,125,233 inflated bytes. 233 badge-major bitset rows, each 125,001 bytes. Membership is `bits[row × 125001 + (number >> 3)] & (1 << (number & 7))`. Ignore the seven padding bits at the end of each row.
- `public/data/*-table.<hash>.json`: runtime transport envelopes generated by `npm run prepare:data`. Each contains `{encoding:"gzip-base64", data:"…"}`. ASCII JSON avoids preview-proxy gzip/binary rewriting; content-addressed filenames prevent stale versions being paired with a newer manifest. The source `.bin.gz` files remain available for offline tests and reproduction but are not fetched by the app.
- `badge-metadata.json`: 233 labels, descriptions, emojis, EP values, family names, and badge rarities, in pinned upstream definition order. `matchingNumbers`, `probabilityPercent`, and formatted `probability` are derived from the bitsets, not estimates.
- `game-index.json`: source/revision, population, row order, compressed and inflated SHA-256 digests/lengths, versioned transport paths, roll-tier thresholds, and tier counts.
- `diagram-hints.json`: observed whole-number contributor categories from reference test cases. Other contributor diagrams are independently derived in `src/contributors.js`. These presentation hints never determine membership or EP. If a helper cannot establish supporting digits, the diagram is omitted; the indexed badge and score remain correct.
- `roll-samples.json`: fifty observed results used **only by tests**. These include contributor outputs and the reference engine’s older approximate percentile; runtime ranks are recalculated from the complete EP population instead. Not imported into the production app.

The upstream executable engine was used only for local inspection. Its implementation and stylesheets are not shipped. The gzip files are factual precomputed indexes, not executable rules. The frontend evaluator independently reads membership, selects the highest-EP badge in each family, and verifies that the resulting total equals the EP index.

### Reproducing the indexes

From the repository root, with GitHub CLI configured:

```sh
revision=8190166af9f259a9d3a0a941b2c9902bfbbe713f
for kind in ep badge; do
  gh api "repos/CubityFirst/rngdle-ep-calculator/contents/site/$kind-table.bin.gz?ref=$revision" \
    -H 'Accept: application/vnd.github.raw+json' > "public/data/$kind-table.bin.gz"
done
npm run prepare:data
npm test
```

Keep the pinned metadata order aligned with `game-index.json` / upstream badge definitions. If changing the source revision, review the metadata, row ordering, and roll-tier thresholds together; do not simply replace one table. Tests audit every legal score, every badge probability, tier counts, hashes, and agreement with fifty reference results. Store no upstream executable engine in production.

## Exact odds

The [Luck page](https://rng.cubityfir.st/luck) uses the exact full-population CDF `F(EP) = count(score ≤ EP) / 1,000,001`. Infinite uses that inclusive CDF and defines the displayed tails explicitly:

- Top: `100 × count(score ≥ this score) / 1,000,001`.
- Bottom: `100 × count(score ≤ this score) / 1,000,001`.
- Ties are included in either displayed tail, so the two tails can sum to more than 100%. The label shows Top when the inclusive CDF is at least 50%.
- Visible ranks use the reference’s whole-percentage rounding and **<1%** when rounding would yield zero. Rank tooltips retain three significant digits (maximum six decimal places), exact integer counts, and tie counts. For example `1337` displays **Top <1%**, with **Top 0.0026%** and 26 matching numbers in the tooltip. The best score’s tooltip shows **Top 0.0001%**, one number.
- Badge odds count all earned badges, including superseded family members. These are per-number occurrence probabilities, not shares of total badges or of this session.
- Each exact integer is equally likely: `1 / 1,000,001`. Web Crypto uint32 rejection sampling discards values at or above **4,294,004,294**, then applies modulo 1,000,001. Never exclude a previous roll; repeats are valid.

Badge rarity and total-roll tier use different scales. The independently observed roll-tier lower bounds and full-range counts are:

| Roll tier | Minimum EP | Numbers |
| --------- | ---------: | ------: |
| Trash     |          0 |  10,114 |
| Common    |      2,087 | 489,889 |
| Uncommon  |      5,802 | 250,028 |
| Rare      |     10,074 | 149,970 |
| Epic      |     22,293 |  50,003 |
| Anomaly   |     35,469 |  39,997 |
| Mythic    |    162,292 |  10,000 |

The runtime worker retains about 37 MB of typed-array indexes (EP, sorted EP, badge membership), with higher temporary memory during loading/decompression. It is initialized lazily on the roll page and reused for the session. The worker fetches the versioned JSON with cache revalidation, base64-decodes its inner payload, then checks the exact decompressed size and canonical SHA-256 before use. This accepts harmless gzip-container metadata or compression changes without ever accepting changed scores. Decompression is bounded to the manifest’s expected size. HTTP Content-Encoding applies only to the outer JSON, not the inner payload. No score or EP is awarded after a loading/integrity failure.

## Animation contract

The frontend preserves the [documented sequence](https://github.com/CubityFirst/rngdle-ep-calculator/blob/8190166af9f259a9d3a0a941b2c9902bfbbe713f/site/README.md#roll-timings):

1. Scramble unrevealed slots every 100 ms. For six slots, land digits at **2,000 / 3,000 / 4,040 / 5,200 / 6,560 / 8,200 ms**. Use seven slots for 1,000,000.
2. Each digit settles for 400 ms. Blank leading slots collapse instead of showing padded zeros. The number card pulses for 700 ms when the final digit lands.
3. After 1,000 ms, reveal the lowest-EP scoring family first. Prepend the next badge group after `500 + 1000 × (i / (n−1))^1.5` ms. Badge cards enter from 20 px above over 350 ms with cubic ease-out. Their EP contributions count up over 500 ms.
4. Show the badge summary 1,500 ms after the last group. Reveal the rarity colours and Share row 1,000 ms later, with a second 700 ms card pulse. Pop in the rank/percentile 250 ms after that.
5. Show the EP wallet 1,000 ms later; begin its 1,500 ms count-up after another 1,500 ms. Lift the 600 ms vignette transition 2,000 ms after the count starts.
6. The values above describe the reference choreography in `buildReferenceTimeline`. Infinite proportionally scales its cue times, digit settles, card pulses, badge entrances, EP count-ups, and rank entrances to a **45-second complete reveal**. Quickwind upgrades reduce the complete reveal to **35, 25, or 15 seconds**.
7. A **60-second base cooldown** starts at completion, including reduced-motion completion. Clockwork upgrades reduce it to **45, 30, or 15 seconds**. Reveal/cooldown settings are snapshotted when starting a roll; purchases never re-time an active reveal or cooldown. Saving EP and cooldown requires a local profile, not an online account; guest changes remain in memory.

Contributor chips highlight in 200 ms with 80 ms staggers, then periodically fade back to resting colours and highlight again. Multi-group contributors have distinct colours; mountains/valleys ripple from the centre. Factor-based badges use a formula rather than arbitrary digit chips. Unrelated badges receive no diagram.

The EP pill is visible as `??? EP` from the start of the spin. Its first contribution animates from zero rather than popping in. Reduced motion cancels the count-up and rank entrance effects and lands on the final totals immediately. There is no manual skip button or keyboard shortcut. Normal reveals retain the reference ordering and proportional pacing while fitting the selected complete duration. Decorative contributor loops retain their original timings.

## Shared number-box appearance

`NumberBox` is the shared presentation for generated rolls, the idle generator, historical roll boxes, and shop previews. The observed scoring-box colours and shadow values in `number-box-palettes.css` come from [Box Lab](https://rng.cubityfir.st/beta/boxes), specifically `SCORE_TIERS` in `src/beta.js` at the pinned upstream revision above. Geometry, markup, and animations are independently implemented. There are separate light/dark gradients, borders, ink colours, and shadows for each of the seven existing tiers; the lab's custom eighth tier is not part of the game. Trash, common, and neutral boxes have no shimmer. Paid cosmetic layers share the same component without changing rarity classification or scoring.
